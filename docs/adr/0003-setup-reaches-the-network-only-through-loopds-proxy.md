# The Setup command reaches the network only through loopd's proxy

The verify command runs offline (ADR 0002), so a stack whose dependencies live in the worktree, such as `node_modules` or `.venv`, needs a Setup command that installs them first, and that command runs code the model can change: `postinstall` scripts and the manifest itself. Seatbelt cannot filter by domain, so the Setup command runs under the verify command's Seatbelt profile, which lets it reach only localhost and resolve no names, with `HTTPS_PROXY` set to a proxy in `loopd` that tunnels `CONNECT` to port 443 of the Loop's `network` domains and ends its tunnels when the Setup command ends; that is no more reach than the Claude Code stages already have, and a tool that ignores the proxy fails closed. The package caches in `~/.loopd/cache` stay shared across Loops, as the Go caches are: an entry one Loop's setup plants still runs only inside another Job's sandbox and ends at a reviewed draft PR. The rejected options were open network with credentials blocked, which lets the Setup command send anything it reads to any host; forcing `--ignore-scripts`, which `loopd` cannot enforce on a command string and which does not cover Python builds; and running setup through Claude Code's sandbox, which puts a model, or a separate runtime dependency, into a deterministic step.
