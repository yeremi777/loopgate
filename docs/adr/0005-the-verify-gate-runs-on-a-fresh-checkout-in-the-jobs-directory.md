# The Verify gate runs on a fresh checkout in the Job's directory

A gitignored file in the Job's worktree, such as a local `.env` or a build output, could make the verify command pass on work the draft PR does not contain, so the gate runs the setup and verify commands on a new detached worktree of the Job's committed HEAD and removes it after every outcome. That checkout lives in `$LOOPD_HOME/jobs/<id>/`, which no gate command may write: in TMPDIR, which they may write, a setup command could rename the checkout or replace its `.git` pointer, and `loopd`'s own unsandboxed `git status` would then read a gitdir the command chose, whose config can run filters as `loopd`. The rejected option was `git clean -fdX` in the Job's worktree, which keeps installed dependencies for later stages but deletes a human's ignored files after a Takeover and does not catch edits inside `node_modules`. In exchange, the Job's worktree no longer gets dependencies from the gate, and each gate installs them again from `~/.loopd/cache`.
