# loopd serves the tracking page on localhost

A Job's tracking page should work like a website: one address on one port for every Job, a tab per Job that survives the terminal that opened it, and a bookmark that still works after a restart. Only `loopd` lives that long, so `loopd` serves the page on `127.0.0.1` at a port it keeps in `$LOOPD_HOME`, behind a random token that lasts as long as that port, a `Host` check and a Content-Security-Policy, answering `GET` only, and `loopctl track` just opens the Job's URL. Every other `loopctl` command still reaches `loopd` only through its unix socket. The rejected option was a short-lived server inside each `loopctl track` call, which leaves `loopd` with no TCP listener but gives each tab its own port and ends the tab's updates when that call ends.
